Сервис коротких ссылок

Консольное приложение на Java 17. Превращает длинную ссылку в короткую, считает переходы
и ограничивает их число, а также автоматически удаляет ссылки по истечении срока жизни.
Пользователи работают без регистрации: каждого определяет UUID, который выдаётся при создании
первой ссылки.


Что умеет сервис

- создаёт короткую ссылку из длинной, у разных пользователей ссылки на один и тот же сайт всегда разные;
- у одного пользователя может быть сколько угодно ссылок;
- при вводе короткой ссылки в консоль открывает исходный сайт в браузере;
- считает переходы и блокирует ссылку, когда лимит исчерпан;
- удаляет ссылку, когда истекает срок жизни; срок задаётся в настройках, а не пользователем;
- присылает владельцу уведомление, когда лимит исчерпан или срок истёк;
- менять лимит и удалять ссылку может только её создатель;
- все основные параметры читаются из файла настроек;
- проверяет ввод и понятно сообщает об ошибках.


Установка и запуск

Понадобятся JDK 17 или новее и Maven. Внешних библиотек, кроме JUnit для тестов, нет.

```
git clone <ссылка на репозиторий>
cd link-shortener
mvn package
java -jar target/link-shortener-1.0.0.jar
```

В IntelliJ IDEA достаточно открыть проект и запустить класс ru.mifi.shortener.App.

Сервис работает локально: короткие ссылки вида clck.ru/abc123 нужно вводить в консоль программы,
а не в адресную строку браузера.


Настройки

Параметры лежат в src/main/resources/application.properties:

```
link.domain=clck.ru              домен короткой ссылки
link.code-length=6               длина кода
link.ttl-minutes=1440            время жизни ссылки в минутах (1440 это сутки)
link.default-max-clicks=10       лимит переходов, если пользователь его не указал
link.max-clicks-limit=10000      максимально допустимый лимит
cleanup.interval-seconds=60      как часто удаляются просроченные ссылки
```

Чтобы поменять настройки без пересборки, положите свой application.properties в папку,
из которой запускаете программу, или передайте путь к файлу первым аргументом:

```
java -jar target/link-shortener-1.0.0.jar /путь/к/application.properties
```


Команды

```
create <url> [лимит]       создать короткую ссылку
<короткая ссылка>          открыть ссылку в браузере (достаточно вставить её в консоль)
open <короткая ссылка>     то же самое через команду
list                       мои ссылки
info <короткая ссылка>     подробности о ссылке
limit <ссылка> <N>         изменить лимит переходов
delete <ссылка>            удалить ссылку
whoami                     показать мой UUID
login <UUID>               переключиться на другого пользователя
logout                     начать как новый пользователь
config                     показать текущие настройки
help                       справка
exit                       выход
```

Если другой пользователь попробует изменить или удалить чужую ссылку, он получит ответ
«Изменять и удалять ссылку может только её создатель». Открывать чужие ссылки может любой.


Как устроен код

Код разделён на три слоя.

core содержит бизнес-логику и не зависит от консоли и браузера:

- model: короткая ссылка и настройки приложения;
- service: создание ссылок и переходы (LinkService), генерация кодов, проверка ссылок,
  пользователи, уведомления, интерфейс для открытия браузера;
- repository: интерфейс хранилища ссылок;
- exception: ошибки ввода, доступа и недоступной ссылки.

infra содержит реализации: хранилище ссылок в памяти, чтение настроек из файла,
открытие браузера через java.awt.Desktop и фоновую задачу очистки просроченных ссылок.

cli отвечает за консоль: разбирает команды, выводит ответы и уведомления.

Класс App читает настройки, собирает все части вместе и запускает цикл чтения команд.

Несколько решений, которые стоит пояснить:

- код ссылки случайный (6 символов из 62 возможных), при совпадении генерируется заново,
  поэтому ссылки всегда уникальны, в том числе для одного и того же сайта у разных пользователей;
- просроченные ссылки удаляются двумя способами: фоновой задачей по расписанию из настроек
  и сразу при обращении к ссылке, поэтому истёкшая ссылка никогда не откроется;
- методы LinkService синхронизированы, потому что фоновая очистка работает в отдельном потоке;
- открытие браузера вынесено в интерфейс, чтобы в тестах не запускать настоящий браузер;
- текущее время передаётся через Clock, поэтому в тестах можно «перевести часы» на час или сутки
  и проверить удаление ссылок без ожидания.


Тестирование

```
mvn test      только тесты
mvn verify    проверка стиля, сборка и тесты
```

В проекте 22 теста на JUnit 5. Они проверяют все сценарии из задания: разные ссылки для разных
пользователей, уникальность кодов, блокировку после исчерпания лимита, удаление ссылок через час
и через сутки, уведомления владельцу, права на изменение и удаление, а также чтение настроек,
проверку ввода и полные сценарии работы через консоль.


Автоматическая проверка

При каждой отправке кода на GitHub запускается GitHub Actions: проверка стиля (Checkstyle),
сборка и тесты. Настройки лежат в .github/workflows/ci.yml и config/checkstyle.xml.
Файл .editorconfig задаёт кодировку и отступы.
